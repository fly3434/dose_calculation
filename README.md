# NS 流速計算 · iPhone 網頁版

本專案為 **HTML / CSS / JavaScript 網頁 App**，可在 iPhone Safari 開啟並加入主畫面。網頁檔案直接放在專案根目錄，可由 GitHub Pages 從根目錄發布。

## 專案結構

```text
dose_calculation/
├── README.md
├── index.html        # 網頁入口
├── styles.css
├── calculator.js     # 計算核心
├── app.js            # 畫面事件
├── sw.js             # 離線快取
├── manifest.webmanifest
├── icon.svg
├── icons/            # 主畫面圖示
├── tests/            # 計算、操作事件與離線快取測試
├── tools/            # 預覽、圖示產生、線上檢查與 Sites 封裝
├── .openai/          # Sites 部署設定
├── .nojekyll         # GitHub Pages 靜態檔案發布
└── package.json
```

## 網頁版使用

已透過 GitHub Pages 公開發布：[開啟 NS 流速計算](https://fly3434.github.io/dose_calculation/)。原始碼：[fly3434/dose_calculation](https://github.com/fly3434/dose_calculation)。任何持有網址的人都可使用，不需登入。已用無 Cookie、無登入憑證的請求確認網站返回 HTTP 200 計算頁。

1. 在 iPhone Safari 開啟網站網址。
2. 點 Safari「分享」→「加入主畫面」；如有「以網頁 App 開啟」選項，將其開啟。
3. 從主畫面開啟一次，等頁面下方顯示「已可離線使用」，之後即可試著在飛航模式使用。

加入主畫面的步驟依 [Apple 使用說明](https://support.apple.com/en-lamr/guide/iphone/iphea86e5236/ios)。第一次載入需連線；離線快取需要 HTTPS 或 localhost，且可能因瀏覽器清除網站資料而失效。計算輸入只保留在當前頁面記憶體，重新開啟恢復預設值。

Windows 上預覽：

```powershell
npm start
```

需要 Node.js 18 以上，沒有第三方 JavaScript 依賴，也不需先執行 `npm install`。在電腦瀏覽器開啟 `http://127.0.0.1:8080`。這個 localhost 地址僅能在該台電腦使用，iPhone 請使用部署後的 HTTPS 網址。

雙擊根目錄的 `index.html` 可在桌面瀏覽器檢視與計算，但 `file://` 不支援離線 Service Worker。預覽伺服器僅提供 App 資源與 PNG 圖示，不公開 Git 歷史、測試、工具或部署設定。

網頁版已通過 41 項 JavaScript / 操作事件 / PWA 邏輯測試，其中計算測試涵蓋 3,600 組輸入邊界。網站部署已確認成功；此環境沒有可用瀏覽器，尚未驗證 iPhone Safari 排版、主畫面安裝與實機離線功能。

已發布 v2 離線修復版：先前 Sites 主機會將 `index.html` 轉址到首頁，舊版快取該轉址回應可能造成瀏覽器 `ERR_FAILED`。新版快取直接回傳的首頁，修復導航時的轉址標記相容性。若曾開啟舊版，請關閉網站分頁再重新開啟；仍出錯可先使用無痕視窗排除舊快取。

## 公式假設（待需求確認）

原需求的「流速 × 24」單位是 mL/day。此實作將袋數定義為 **流速 × 24 ÷ 500**。每袋固定 500 mL；NS 指 0.9% 氯化鈉。500 mL 容器的來源：[DailyMed 容器標示](https://dailymed.nlm.nih.gov/dailymed/drugInfo.cfm?setid=7f22c06b-6b4d-4b49-a4b2-d2169f2bd653)。此來源僅確認產品標示，不代表本工具的分班演算法經臨床驗證。

「剩餘量 ÷ 剩餘小時 × 日班剩餘小時」的單位是 mL，不能顯示為流速。同時，各班都用完整剩餘量 ÷ 8 會重複分配。因此暫採以下共同分配規則，尚未得到使用者對修正公式的確認：

- 已輸入量 = 目前流速 × 從當日 08:00 起經過的小時。
- 新目標 = 修正後袋數 × 500。
- 剩餘需輸入量 = 新目標 − 已輸入量，保留正負號。
- 各班剩餘時間 = 該班與「變更時間至隔日 08:00」的重疊小時。
- 預設所有仍有剩餘時間的班別，以「剩餘需輸入量 ÷ 全部剩餘小時」設定相同流速。
- 使用者修改某班後，該班固定；**其餘尚未手動修改的班別**以「剩餘量 − 已固定班別流速 × 時間」除以其共同剩餘小時，重新分配。
- 可固定一、二或三班。全部固定時，保留設定並顯示差額；可點「恢復自動」解除某班固定。
- 每個流速先四捨五入至整數（0.5 向上），再計算各班量及總量。袋數、袋數換算結果不四捨五入成整袋；修正前袋數顯示至小數三位。
- 總剩餘劑量 = 修正後每日目標 − 已輸入量，表示目標尚需輸入的量。
- 預計輸入劑量 = 三班目前設定的整數流速 × 各班剩餘小時的加總，含手動固定與自動連動的班別；未套用草稿不計入。
- 差額 = 預計輸入劑量 − 總剩餘劑量；正值超出、負值不足。畫面顯示「與目標劑量多了／少了／一樣」，搭配差額的絕對 mL 數，避免使用者解讀正負號。四捨五入後可能不精確等於目標，不會隱藏差額。

原描述第 3.3 項提到大夜班自己調整自己；本實作統一採上述固定班別與自動班別規則。

## 輸入與操作

| 欄位 | 範圍 | 步距 |
| --- | --- | --- |
| 目前流速 | 5–500 mL/hr | 5 |
| 修正後總袋數 | 0.5–24 bag/day | 0.5 |
| 變更時間 | 當日 08:00–隔日 08:00 | 1 小時 |

三班都同時提供滑桿與小數數字欄位；數字欄輸入後按「套用流速」或 Enter 才生效，輸入的小數在套用時四捨五入。點選欄位時游標預設位於數字右側，套用與取消按鈕靠右。可取消未套用的編輯；修改主要輸入或其他班別會清除未套用草稿。

流速滑桿每格增減 5 mL/hr。目前流速使用 5–500 的範圍，避免 `min=1, step=5` 造成 500 無法選取。各班自動流速仍四捨五入至整數，不強制取 5 的倍數；滑桿以目前整數值為基準（例如 84 → 89），數字欄可微調或設為 0。各班滑桿上限依剩餘量及手動值延伸，至少涵蓋 500；**輸入流速的 500 上限不是輸出流速的醫療安全上限**。

## 班別與交班袋數

班別顯示為日班 `08:00-15:59`、小夜班 `16:00-23:59`、大夜班 `24:00-隔日07:59`。計算仍使用 08:00、16:00、24:00、隔日 08:00 的交接界線，每班完整時段為 8 小時。

在日班與小夜班之間、小夜班與大夜班之間顯示「目前這袋剩 360 mL NS（0.72 袋）」的格式，mL 數字為較大的主數字，袋數放在括號內。此定義暫依「每天 08:00 更新滿袋」理解，表示正在掛著的袋子，而不是當日目標剩餘總袋數；交班的實際記錄仍需自行核對。

每天 08:00 從 500 mL 滿袋起算，假設每袋輸完後接續換新袋。先累計變更前的輸入量與之後各班規劃量，到 16:00、24:00 計算；目前這袋剩餘量為 `500 −（累計量 % 500）`。累計為 0 時保留 500 mL；累計恰好為 500 的正整數倍時顯示 0 mL 並提醒換新袋。袋數＝剩餘 mL ÷ 500，最多顯示三位小數。

例如預設條件累計到 16:00 為 656 mL，第二袋已輸入 156 mL，所以交班剩 344 mL（0.688 袋）。若變更時間已超過交班點，顯示「已交班，依變更前流速回推」，不當成實際紀錄。

修改三個主要輸入會清除手動設定，避免把舊醫囑的分配帶入新條件。班別已結束時，剩餘小時、流速與分配量均為 0，停用控制項。未開始的班別計完整 8 小時。

目標已達成／已超出時各班顯示 0，不將負量轉成負流速；此顯示是數學結果，不是停液醫囑。隔日 08:00 不除以零，會顯示未完成的量。手動固定量超出目標時，保留手動值，其他班顯示 0 並提示衝突。

數字欄驗證有限、非負的 JavaScript 數值，並設數值表示上限以防超出安全整數範圍；這不是臨床流速上限。未設定通用臨床安全閾值，因本需求未提供院內規範。

## 試算範例

目前 80 mL/hr、修正後 4 袋、12:00 變更：

- 修正前 3.84 袋／日；已輸入 320 mL；剩餘 1,680 mL。
- 日班剩餘 4 小時，小夜與大夜各 8 小時。
- 預設三班 84 mL/hr，分配 336 + 672 + 672 = 1,680 mL。
- 日班改為 100 mL/hr：小夜、大夜自動改為 80 mL/hr，400 + 640 + 640 = 1,680 mL。
- 再固定小夜 90 mL/hr：大夜自動改為 70 mL/hr，400 + 720 + 560 = 1,680 mL。

同樣醫囑於 20:00 變更：剩餘 1,040 mL，剩餘 12 小時，自動流速 87 mL/hr；總量 1,044 mL，清楚顯示 **+4 mL** 差額。

## GitHub Pages 部署

已建立公開儲存庫 `fly3434/dose_calculation`，GitHub Pages 已設定為 `main` 分支的 `/(root)`。後續提交並 push 至 `origin/main`，GitHub 會自動更新網站。

1. 將根目錄的專案檔案提交至 GitHub 儲存庫（不要上傳 `.git/`）。使用 GitHub 免費方案時，儲存庫需為公開。
2. 在儲存庫開啟 **Settings → Pages**。
3. Source 選 **Deploy from a branch**，Branch 選 `main`，資料夾選 `/(root)`，按 Save。
4. 等待發布成功，網站網址通常為 `https://你的帳號.github.io/儲存庫名稱/`。

根目錄已有 `index.html` 與 `.nojekyll`，不需要建置步驟或 GitHub Actions。HTML、Manifest 與離線程式使用相對路徑，支援儲存庫的網站子路徑。設定方式見 [GitHub Pages 官方說明](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。

## Sites 部署與版本更新

目前主要發布位置為 GitHub Pages。原有 Sites 網址 `https://ns-flow-calculator.bloomyiris6.chatgpt.site` 與 `.openai/hosting.json` 的 `project_id` 已保留，可作為另一個部署來源。因 Sites 封裝工具需使用獨立輸出資料夾，部署前執行：

```powershell
npm run build:site
```

工具會將 10 個公開資源複製到 `build/`，`.openai/hosting.json` 的 `static.directory` 已指向該資料夾。`build/` 是可重新產生的部署輸出，已被 Git 忽略，不是原始碼位置；GitHub Pages 不需要執行這一步。此整理只改變本地檔案位置，既有 Sites 網址仍使用上次發布的版本。

更新任一 App 資源時，需遞增 `sw.js` 的 `CACHE` 版本。新版本會先在背景下載，頁尾顯示「更新版本（重設輸入）」；使用者點擊後才載入新版本。v2 修復版在偵測到 v1 快取時會自動接管，以修復舊版無法開啟更新介面的問題，不強制重載正在輸入的頁面。

## 開發工具與資料

`tools/generate_icons.py` 可重新產生 `icons/` 下的主畫面圖示，需要 Python 與 Pillow。`tools/build_site.cjs` 處理 Sites 部署輸出，`tools/serve.cjs` 提供本機預覽。

計算在瀏覽器內完成，不將輸入值傳送到伺服器；無第三方 JavaScript、字型或統計追蹤。離線快取只存程式與圖示，計算輸入只保留在當前頁面的記憶體。重新開啟會恢復 80 mL/hr、4 袋、12:00 的預設條件。Safari 與主畫面 App 的儲存可能分開，請在主畫面 App 確認「已可離線使用」。瀏覽器清除網站資料或系統回收儲存空間後，需重新連線下載。
